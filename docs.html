Novora documentation

Novora is a feature-rich web framework for building APIs and web servers with Node.js or Bun, using JavaScript or TypeScript. It wraps Fastify with a focused API and re-exports a broad set of useful integrations.

Runtime requirements

Node.js 22 or newer. Bun 1.2 or newer is supported; Bun can execute TypeScript files directly.

Installation

Install the package directly from the GitHub repository.

npm
npm install github:0XOPx/Novora
Bun
bun add github:0XOPx/Novora

Novora publishes ESM, CommonJS and TypeScript declaration files in its package build. Import from novora, or use the ./cache, ./validation, ./config and ./errors subpaths.

Quick start

Create an application, register any plugins you need, define routes, and start listening.

server.js
import { Novora, cors, helmet, compress, rateLimit } from "novora";

const app = new Novora({ logger: true });

await app.register(cors, { origin: true });
await app.register(helmet);
await app.register(compress);
await app.register(rateLimit, { max: 100, timeWindow: "1 minute" });

app.get("/", async (request, reply) => {
    return reply.send({ message: "Hello from Novora!" });
});

app.health();

await app.listen(3000);

TypeScript

Novora exports its public Fastify types and its own option and plugin aliases. With Node.js, run TypeScript using a compatible loader such as tsx, or compile it first. Bun supports native TypeScript execution.

server.ts
import { Novora, z, validate } from "novora";

const app = new Novora({ logger: true });

app.route({
    method: "POST",
    url: "/users",
    preHandler: validate({
        body: z.object({
            name: z.string().min(1),
            email: z.string().email()
        })
    }),
    handler: async request => ({
        created: true,
        user: request.body
    })
});

await app.listen({ port: 3000, host: "0.0.0.0" });

Application API

Create an app with new Novora(options). The constructor accepts Fastify server options and creates the underlying Fastify instance.

new Novora(options?)

Create a Novora application. options uses FastifyServerOptions.

createNovora(options?)

Factory function returning a new Novora instance.

app.server

Read-only access to the underlying FastifyInstance.

app.instance

Getter alias for the underlying Fastify instance.

app.validate(schemas)

Create a validation pre-handler from body, params, query or headers schemas.

app.setErrorHandler(handler)

Install a custom error handler. Novora-aware HTTP errors are serialized to JSON with status, code, message and details.

app.setNotFoundHandler(handler)

Set the Fastify not-found route handler.

Routing

Route helpers accept a path and a Fastify route handler. They return the app instance, so route setup can be chained.

app.get(path, handler)

Register a GET route.

app.post(path, handler)

Register a POST route.

app.put(path, handler)

Register a PUT route.

app.patch(path, handler)

Register a PATCH route.

app.delete(path, handler)

Register a DELETE route.

app.head(path, handler)

Register a HEAD route.

app.options(path, handler)

Register an OPTIONS route.

app.all(path, handler)

Register a route for GET, POST, PUT, PATCH, DELETE, HEAD and OPTIONS.

app.route(options)

Register a full Fastify RouteOptions object. Use this form for route-level options such as preHandler, schema, config and handler.

Routers and groups

new Router(prefix?)

Create a route collection with an optional path prefix.

router.route(options)

Add a Fastify route definition with the router prefix applied.

router.get/post/put/patch/delete/head/options/all(path, handler)

Convenience methods for defining routes on a Router.

router.mount(router)

Copy another router's route definitions into this router.

router.definitions

Read the router's route definitions.

app.mount(router)

Mount a router's definitions on the application.

app.group(prefix, callback)

Create a prefixed router, pass it to the callback, then mount it.

createRouter(prefix?)

Factory function returning a new Router.

Grouped routes
import { Novora, Router } from "novora";

const app = new Novora();
const api = new Router("/api/v1");

api.get("/status", async () => ({ status: "ok" }));
api.get("/users/:id", async request => ({ id: request.params.id }));

app.mount(api);

app.group("/admin", router => {
    router.get("/dashboard", async () => ({ page: "dashboard" }));
});

await app.listen(3000);

Plugins, hooks and decorators

app.register(plugin, options?)

Register a Fastify callback or async plugin.

app.use(plugin, options?)

Alias for register.

app.addHook(name, hook)

Register a Fastify lifecycle hook. The hook name and callback follow Fastify's hook API.

app.decorate(name, value)

Add a Fastify decorator.

Plugin registration is asynchronous in effect; await app.ready() when you need all plugins and routes to be initialized before continuing.

Health endpoint

app.health(path?) adds a GET endpoint at /health by default. The response includes status, detected runtime, process uptime and an ISO timestamp. The method returns the app instance.

Health response
{
  "status": "ok",
  "runtime": "node",
  "uptime": 42.5,
  "timestamp": "2026-11-22T12:00:00.000Z"
}

Server lifecycle and testing

app.listen(portOrOptions?)

Start the server. A numeric port listens on 0.0.0.0; omitted options default to port 3000 on 127.0.0.1. An options object uses Fastify listen options.

app.ready()

Await Fastify initialization and return the Novora app.

app.close()

Close the server and await completion.

app.inject(options)

Perform an in-process Fastify injection request, useful for tests without opening a network port.

app.printRoutes()

Return Fastify's printed route tree.

Validation

Novora re-exports Zod as z and provides validate(schemas), a Fastify pre-handler for request validation.

Supported schema keys are body, params, query and headers. Each schema uses Zod's safeParse. On failure, the request receives HTTP 400 with error: "VALIDATION_ERROR", a message and the Zod issue list. On success, parsed data is assigned back to the request property.

Validation
import { Novora, z, validate } from "novora";

const app = new Novora();

app.route({
    method: "POST",
    url: "/users",
    preHandler: validate({
        body: z.object({
            username: z.string().min(3),
            email: z.string().email()
        })
    }),
    handler: async request => ({ user: request.body })
});

Exports: validate, validateWith, ValidationSchemas and ValidationFailure.

TTL cache

TTLCache is a small in-memory cache with per-entry expiration and a maximum entry count. The default TTL is 60,000 ms and the default maximum is 10,000 entries.

new TTLCache(options?)

Options: defaultTtl in milliseconds and maxEntries.

cache.set(key, value, ttl?)

Store a value. A TTL of zero means no expiration. Returns the cache.

cache.get(key)

Get a value, or undefined when missing or expired.

cache.has(key)

Check whether a non-expired value exists.

cache.delete(key)

Delete one key and return whether it existed.

cache.clear()

Remove all entries.

cache.clearPrefix(prefix)

Remove keys beginning with a prefix and return the number removed.

cache.size

Get the number of non-expired entries.

cache.getOrSet(key, factory, ttl?)

Return an existing value or create, store and return one.

createCache(options?)

Factory function returning a TTLCache.

Invalid negative or non-finite TTL values throw a RangeError. When capacity is reached, adding a new key evicts the oldest inserted key.

Configuration

Configuration helpers use dotenv and Zod. loadConfig optionally loads an environment file, then parses process.env using the supplied schema.

config.ts
import { loadConfig, z } from "novora";

const config = loadConfig({
    schema: z.object({
        PORT: z.coerce.number().default(3000),
        NODE_ENV: z.enum(["development", "production", "test"]).default("development")
    }),
    path: ".env"
});
loadConfig({ schema, path?, override? })

Load dotenv values and parse process.env. override defaults to false.

parseConfig(source, schema)

Parse a supplied object with a Zod schema without loading dotenv.

ConfigOptions

Type containing schema, optional path and optional override.

Errors

NovoraError extends Error and carries statusCode, code and optional details. Use the helpers to create consistent HTTP errors.

new NovoraError(message, statusCode?, code?, details?)

Construct a Novora-aware error. Defaults: 500 and NOVORA_ERROR.

createError(statusCode, message, code?, details?)

Factory for a NovoraError.

badRequest(message?, details?)

HTTP 400 · BAD_REQUEST.

unauthorized(message?)

HTTP 401 · UNAUTHORIZED.

forbidden(message?)

HTTP 403 · FORBIDDEN.

notFound(message?)

HTTP 404 · NOT_FOUND.

conflict(message?, details?)

HTTP 409 · CONFLICT.

tooManyRequests(message?)

HTTP 429 · TOO_MANY_REQUESTS.

internalServerError(message?)

HTTP 500 · INTERNAL_SERVER_ERROR.

When you install a custom handler using app.setErrorHandler, Novora serializes NovoraError instances and errors with HTTP status codes from 400 to 599 as JSON.

Exported types

  • NovoraOptions — alias of FastifyServerOptions.
  • NovoraPlugin — Fastify callback or async plugin type.
  • ValidationSchemas — optional body, params, query and headers Zod schemas.
  • ValidationFailure — validation error response shape.
  • CacheOptions — defaultTtl and maxEntries.
  • ConfigOptions<T> — schema, path and override.
  • FastifyInstance, FastifyListenOptions, FastifyPluginAsync, FastifyPluginCallback, FastifyServerOptions, RouteHandlerMethod, RouteOptions, InjectOptions.
